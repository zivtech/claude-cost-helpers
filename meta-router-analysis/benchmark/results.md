# Meta-skill loading-strategy benchmark

Generated by `meta-router-analysis/benchmark/scenarios.py`. Reproducible from a clean checkout:

```bash
cd meta-router-analysis/benchmark
python3 scenarios.py --markdown > results.md
```

The script clones both [zivtech/drupal-meta-skills](https://github.com/zivtech/drupal-meta-skills) and [zivtech/a11y-meta-skills](https://github.com/zivtech/a11y-meta-skills) at two refs each:

- `main` — the bundle's current default-branch state ("before").
- `router-v2-trim` (drupal) / `router-v2-refactor` (a11y) — the public branches that adopt the router-v2 pattern ("after").

Thresholds (from this repo's helpers):

- **Rot zone** — 300,000 tokens. Source: `just-one-more-turn/` (`CLAUDE_CONTEXT_THRESHOLD` default).
- **Subagent-isolation warning** — 50 unique files. Source: `subagent-isolation/` (`CLAUDE_FILE_THRESHOLD` default).
- **Cache TTL** — 300 seconds. Source: `idle-tax/` (Anthropic prompt-cache TTL).

Token counts use the `char/4` estimator also used by `watching-cost/` and `just-one-more-turn/`. Treat results as a rough floor, not a precise ceiling. Relative differences between strategies are robust to that approximation.

## The three strategies

- **F. Flattened (straw-man).** Every SKILL.md body and every agent body preloaded into the parent context at turn 1. Represents "what if the router pattern were inlined instead of delegated to subagents?"
- **A. As-implemented.** What the bundle does at the measured ref. SKILL.md bodies enter the parent context when the bundle is installed (that is how agent clients work today). Agent bodies stay on disk and are only loaded when an `Agent(subagent_type=...)` call spawns them; those bodies live in a subagent context and return only a summary to the parent.
- **C. Optimized (simulated).** SKILL.md files shrunk to frontmatter-only stubs; router prompt + subagent handoff. See `../improvements/router-v2-spec.md`. This row is a prediction; comparing it to the empirical "after" rows below validates the prediction.

## What the numbers show

1. **The router-to-agent pattern works.** drupal-meta-skills' default state already saves 83% vs the flattened straw-man. The `router-v2-trim` branch tightens that to 88% by removing implementation-detail sections from SKILL.md without touching agents.
2. **Inline protocols are the expensive failure mode.** a11y-meta-skills shipped agents but duplicated the full protocol inside SKILL.md. The `router-v2-refactor` branch moves the protocol into agents (no content lost) and the bundle drops from 14% of the rot zone at turn 1 to 0.5%.
3. **The simulation is a trustworthy predictor.** The a11y "after" A row (1,465 tokens) lands within 4% of the simulated C row (1,410 tokens) for the same bundle. If you want to estimate router-v2 savings on a bundle before refactoring, the simulator is good enough.
4. **Stubs are cheap.** 657 tokens for eight drupal stubs; 410 for four a11y stubs. The stub layer is a fixed cost that buys a routing decision without loading any body.
5. **The 50-file subagent-isolation warning is not at risk.** Worst case is 16 files for the drupal F straw-man — still well under threshold. After scenarios use ≤8.

## Cache-cold exposure

With the `idle-tax` 5-minute TTL, "volatile tokens" are the tokens a cold-cache event forces to re-cache at 1.25× base cost:

- **drupal-meta-skills (before):** 8,807 volatile tokens. Tolerable.
- **drupal-meta-skills (after):** 5,891. -33%.
- **a11y-meta-skills (before):** 41,649. `idle-tax/` fires a hard warning at this size.
- **a11y-meta-skills (after):** 965. **-98%.** A cold-cache event in the parent session no longer forces expensive skill-body re-caching.
